# AI Lead Intelligence

AI Lead Intelligence is a full-stack improvement for the SaaSQuatch Leads challenge. Instead of scraping more raw prospects, it helps a sales user answer the next and more valuable question: which leads should be contacted first, and why?

## Product Overview

The app imports leads from CSV or a realistic demo dataset, normalizes and deduplicates records, scores each lead against an Ideal Customer Profile, ranks opportunities, and gives a concise AI or deterministic fallback explanation. The numerical score is never generated by AI.

## Why This Feature

Lead volume alone does not create sales value. SaaSQuatch already focuses on discovery, enrichment, and outreach generation, so this project targets the next bottleneck: prioritization. Sales teams need transparent fit, contactability, growth, and data-quality signals before spending time on outreach.

## Tech Stack

- Frontend: React, TypeScript, Vite, Tailwind CSS, lucide-react
- Backend: Node.js, TypeScript, Express
- Database: PostgreSQL through `pg`
- CSV: `@fast-csv/parse` and `@fast-csv/format`
- Tests: Vitest

## Architecture

The application is a full-stack TypeScript monorepo with two npm workspaces: a React SPA frontend and an Express API backend, backed by PostgreSQL.

The backend uses a feature-first structure under `backend/src/features`. Each feature owns its routes, controller, service, repository, validation, and types where needed. Controllers are thin HTTP adapters. Scoring, AI, import, and deduplication logic can run independently of Express.

## Key Features

- `users`: demo-safe user creation and lookup
- `icp`: ICP creation, update, listing, and demo ICP
- `leads`: list, detail, pagination, filtering, sorting
- `import`: CSV/demo import, validation, normalization, deduplication
- `deduplication`: merge duplicate-like records by domain/email/LinkedIn/company
- `scoring`: deterministic 0-100 scoring
- `ai`: provider abstraction, Groq/OpenAI-compatible provider, fallback explanation
- `dashboard`: aggregate sales stats
- `export`: implemented through `/api/leads/export`

## How It Works (Data Flow)

The core value of the app is turning a raw lead list into a prioritized, explainable list of who to contact first:

```
  CSV file / demo data
        │
        ▼
  ┌─────────────┐   sanitize rows, map fields (aliases),                   
  │   import    │   normalize phone/email/domain, parse revenue/employees   
  │   endpoint  │   (import.service.ts → normalizeLead)                    
  └──────┬──────┘
         ▼
  ┌──────────────────┐   merge rows that share domain / email / LinkedIn    
  │  deduplication   │   or a normalized company name; keep one, merge gaps 
  │  mergeDuplicates │   (deduplication.service.ts)                         
  └──────┬───────────┘
         ▼
  ┌───────────────┐   delete the user's prior leads, insert unique rows    
  │  persist      │   (deleteUserLeads + insertLeads)                      
  └──────┬────────┘
         ▼
  ┌─────────────────────────────────────────────┐                          
  │  scoring vs an ICP (scoring.rules.ts)       │  weighted 0-100          │
  │  industry · size · revenue · growth ·       │  reproducible, no AI in  │
  │  contactability · decision maker · quality  │  the numeric score        │
  └──────┬──────────────────────────────────────┘                          
         ▼
  ┌──────────────┐   paginated, filtered, server-side sorted list,          
  │    rank      │   rank #1 = highest opportunity score                    
  │  /api/leads  │   smart filters + manual filters + export                
  └──────┬───────┘
         ▼
  ┌──────────────┐   on-demand AI or deterministic fallback narrative per   
  │  explanation │   lead (why, recommended channel, outreach angle)        
  └──────────────┘
```

Walk-through of the demo flow:
1. **Load Demo ICP** → `POST /api/icp/demo` creates a realistic target profile.
2. **Load Demo Leads** → `POST /api/leads/demo` imports/normalizes/deduplicates the built-in dataset.
3. **Analyze Leads** (with an ICP selected) → `POST /api/leads/analyze` scores every lead against the ICP and stores the results.
4. The leads table then ranks opportunities; click any lead for the score breakdown and an AI explanation.

You can equally **upload your own CSV** via the **Upload CSV** button (`POST /api/leads/import`) instead of using the demo dataset, then select (or create) an ICP and click **Analyze Leads** to score them.

## Database

Migration: `backend/src/shared/database/migrations/001_init.sql`

Tables:

- `users` — app users (a demo user is seeded on migration)
- `icps` — Ideal Customer Profiles (industry, locations, size/revenue ranges, target titles, keywords)
- `leads` — imported/normalized prospect records
- `lead_scores` — one deterministic score per `(lead, icp)` pair, plus cached AI explanation
- `lead_signals` — extracted signals (extensible)

Indexes speed up lead domain, company, industry, state, user id, score lead/id ICP id, and total score lookups.

## How Scoring Works

The central configuration lives in `backend/src/features/scoring/scoring.rules.ts`.

- Industry Fit: 20%
- Company Size Fit: 15%
- Revenue Potential: 15%
- Growth Signals: 15%
- Contactability: 15%
- Decision Maker Fit: 10%
- Data Quality: 10%

Each sub-score is computed deterministically (industry match against the ICP, employee/revenue range fit, growth signal hits, available contact channels, decision-maker title, and present fields), then combined by weight into a 0-100 `total_score`. The score is reproducible: the same lead plus the same ICP always returns the same score. AI receives the score and breakdown only after scoring is complete — the numeric score is never generated by AI.

## AI Architecture

AI is provider-agnostic:

`AIService -> AIProvider -> GroqProvider / CompatibleProvider`

Environment variables:

```bash
AI_PROVIDER=groq
AI_API_KEY=
AI_MODEL=llama-3.1-8b-instant
AI_BASE_URL=https://api.groq.com/openai/v1
```

If `AI_API_KEY` is missing, the app still imports, deduplicates, scores, ranks, filters, exports, and displays deterministic fallback explanations.

## Local Development

### Prerequisites

- Node.js 18+ (workspace uses npm workspaces and `tsx`)
- PostgreSQL running locally (or a remote `DATABASE_URL`)

### Setting up the environment

1. Copy the example environment file and adjust values:

   ```bash
   cp .env.example .env
   ```

   At minimum set `DATABASE_URL` to your PostgreSQL connection string (see [Environment](#environment)).

2. Run the migrations (creates tables + seeds the demo user) and the seed:

   ```bash
   npm install
   npm run migrate -w backend
   npm run seed -w backend
   ```

### Running the app

```bash
npm run dev
```

This starts both workspaces concurrently:

- **Frontend**: `http://localhost:5173`
- **Backend**: `http://localhost:5000`

Then open the frontend and try the demo flow: **Use Demo ICP** → **Load Demo Leads** → **Analyze Leads**, or use **Upload CSV** to score your own file.

### Useful scripts

```bash
npm run build          # build backend (tsc) + frontend (vite build)
npm run test           # run backend Vitest tests
npm run dev -w backend # backend only (tsx watch)
npm run dev -w frontend# frontend only (Vite)
npm run migrate -w backend
npm run seed -w backend
```

## Performance And Caching

Lead listing uses server-side pagination and database-side filtering/sorting. Bulk scoring calculates in-process and persists scores in PostgreSQL. AI explanations are generated only on demand and stored in `lead_scores.ai_explanation`, avoiding repeated model calls.

Redis is intentionally omitted for this MVP. It could be added later for expensive aggregate caching, background jobs, or multi-tenant rate-limit state.

## Security

The app uses environment variables for secrets, request validation, CSV size limits, safe CSV parsing, sanitized error responses, Helmet, CORS, and rate limiting on AI explanation requests. API keys are never exposed to the frontend.

## Deployment

Keep deployment simple:

- Frontend: static deployment
- Backend: Node.js service
- Database: managed PostgreSQL

No Kubernetes, microservices, GraphQL, Prisma, MongoDB, Redis, Redux, or LangChain are required for the challenge scope.

## Tradeoffs And Future Work

This MVP uses a demo user instead of full authentication. A production version would add auth, tenant isolation, richer validation confidence, background scoring jobs, score versioning, and integrations with CRM/outreach systems.
